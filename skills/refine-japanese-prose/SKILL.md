# refine-japanese-prose

日本語文書を平易化する。「書く時」と「書いた後」の両方で使える。適宜更新する前提。

## 使うとき

- 既存の日本語文書(レポート/ブログ/技術文書/メール)を推敲する
- AI生成テキストの臭いを消したい
- 学術過剰な漢語・カタカナを平易化したい
- 馴染みの薄い表現を読みやすくしたい

## 修正観点 (6カテゴリ)

### (1) 馴染みの薄い学術・批評理論用語
- 哲学/批評理論: 還元, 内省, 表象, 相対化, 立脚, 投影, 趣向, 契機, 主観, 客観, 被造物
- 物語論: 構図, 構造, 動員, フレーミング, 影響史, 系譜, 投射, 前面に出る
- 文語的副詞句: 〜のさなか, 〜下で, 後景に退く, 立ち上がる, うかがえる, 根ざす, 反復する, 〜であった

### (2) 不用意な漢字連続
- 5字以上の漢字連続(固有名詞・引用を除く)
- 「普通名詞句 + 固有名」の連結 (例: 「日本人少年正太」 → 「日本人の少年、正太」)
- 造語的複合語 (例: 「人造人間表象」「内面情報」「思考読み取り装置」)
- 3字熟語のうち馴染みの薄いもの (被造物 等)

### (3) カタカナ語のAI臭
- 学術カタカナ語: バリエーション, フレーミング, ヤマ場, シナリオ, ラスト, クライマックス(用途次第)
- 固有名詞・専門用語(LAWS等)は除外

### (4) AI生成の典型構文
- 自己言及: 「本稿は〜論じる」「本論で扱う」「以下、〜する」
- 形式的命名宣言: 「便宜的に〜と呼ぶ」「〜と位置付ける」「(以下〜)」
- 中庸結語: 「〜うる」「〜だろう」「〜とも言える」「〜と読める」「〜と読み直せる」「〜ことが多い」「〜とは限らない」
- 二項対比反復: 「Aではなく Bである」「普遍主義 vs ナショナリズム」
- メタファー結語: 鏡, 触媒, 縮図, 逆照射, 手掛かり, 材料
- 律儀すぎる補足: 初出全員フルネーム+著作カッコ, 英語フルスペル併記

### (5) 内輪言及
- 「課題が言う」「本稿は」「先生が」など、その場限りの文脈に閉じた言及
- 出典は文末括弧で抽象化 or 受動形で文意保持

### (6) ダッシュ「――」と中黒「・」
- ダッシュは「である」「すなわち」「(...)」に置換
- 列挙の中黒は読点「、」に置換
- 固有名(カレル・チャペック等)の中黒は維持

## AI生成典型構文の回避例

| Before | After |
|---|---|
| 本稿は〜を論じる | (削除 or 「以下、〜を見る」) ※ただし「以下、〜」も AI 臭 |
| 便宜的に〜と呼ぶ | 命名宣言を本文の流れの結果として最後に出す |
| 〜とも言える | (削除して断定) |
| 〜である以前に〜地続きで語られる | 〜とは限らない。多くはまず〜として現れる |
| Aではなく Bである | 二項対比は最大1回。3箇所以上あれば1〜2箇所を別構文 |
| 〜うる/しうる | (削除して断定 or 「〜できる」「〜になる」) |
| 鏡として機能する / 逆照射する手掛かり | (メタファー結語は禁止。具体動詞へ) |

## 数字表記の統一ルール

- 章番号と本文中の年号・序数を同じスタイル(算用 or 漢数字)に揃える
- 作中固有番号(第十九番スイッチ等)・引用(講義第三回等)は原典に従う(統一の例外)

## 修正ワークフロー (反復)

1. **lint**: `python -m ja_prose_lint <file>` で機械的検出。high(主に pos_errors)はノイズ多めだが、`continuous_kanji` `repeated_phrases` は有用
2. **agent レビュー**: 下記 prompt テンプレで agent を起動、観点別に候補を抽出
3. **候補提示**: 高/中/低 優先度 + 維持判断で整理、ユーザ判断を仰ぐ
4. **Edit**: ユーザ選択を Edit で適用
5. **(必要なら) PDF 再生成**: 学術レポート提出時のみ
6. **再度 agent レビュー**: 残存・新規指摘を抽出、ループ
7. 「高」がゼロになるまで繰り返す。「中」「低」はユーザ判断

## agent prompt テンプレート

agent (general-purpose) に渡す prompt:

```
あなたは日本語文書のレビュアー。以下の文書を読み、AI生成テキストや学術過剰な表現を平易化する候補を抽出してください。

# 対象ファイル
<file path>

# チェック観点
[skill 内の (1)-(6) をここに展開]

# 出力形式
各候補について:
- 該当箇所(節/原文)
- 問題カテゴリ((1)-(6) のいずれか)
- 推奨修正案(複数候補可)
- 優先度(高/中/低)
- 維持判断のもの は別カテゴリで出力

# 注意
- 固有名詞 / 専門用語 / 直接引用は触らない
- これまでの修正履歴があれば伝えて、重複指摘を避ける

# 既に適用済の修正 (重複指摘しないこと)
[累積した修正履歴を列挙]

# 出力先
<output path>
```

## 補助スクリプト (オプション)

### PDF生成 (学術レポート用、pandoc + lualatex + luatexja)

日本語と英字の間の自動アキを消す YAML フロントマター:

```yaml
---
header-includes: |
  \ltjsetparameter{xkanjiskip=0pt}
  \ltjsetparameter{kanjiskip=0pt plus 0pt minus 0pt}
---
```

pandoc コマンド例:
```bash
pandoc input.md -o output.pdf \
  --pdf-engine=lualatex \
  -V documentclass=ltjsarticle \
  -V geometry:margin=2.5cm \
  -V fontsize=11pt
```

### ja-prose-lint 集計

```bash
python -m ja_prose_lint <file> --output result.json
python -c "
import json
from collections import Counter
data = json.load(open('result.json', encoding='utf-8'))
findings = data['findings']
print('high:', sum(1 for f in findings if f['severity']=='high'))
print('medium:', sum(1 for f in findings if f['severity']=='medium'))
print('low:', sum(1 for f in findings if f['severity']=='low'))
print()
print('detector別:')
for d, n in Counter(f['detector'] for f in findings).most_common():
    print(f'  {n:3d} {d}')
"
```

## 注意点

- **トレードオフ**: 「論理装置(操作的定義/留保強度/問題提起)」と「AI臭の表現」 は同じ表現空間で競合する。両立は構造的に難しいが、命名宣言を本文末に押しのける/留保語を平易動詞句で置換 等で両立可能
- **往復回避**: agent は新しい指摘を生み出すことがあるが、ユーザの直前判断と方向性が逆になる場合は往復しない
- **論文 vs エッセイ**: 「である」調が標準だが、媒体次第で「です・ます」 や口語混じりもあり。skill は文体を強制しない
- **専門用語の維持**: 本論の中核概念・固有名詞・直接引用は触らない

## 自己改善 (skill 自身の更新)

skill を使う中で得た新パターンは、Claude が SKILL.md に追記して育てる。

### 追記の判断基準
- **自動追記OK (ユーザ承認不要、1行告知のみ)**:
  - 明確な単語置換 (例: 還元→単純化)
  - 既知カテゴリの構文パターン追加 (例: 「〜うる」 系の新例)
  - 観点漏れの追記 (既存6観点に収まる範囲)
- **要確認 (ユーザに提案してから追記)**:
  - 既存対応表と矛盾するもの
  - 文脈依存性が強いもの (用途・媒体で逆方向の判断になる)
  - 新カテゴリ (観点) の追加
  - ワークフローの大幅変更

### 追記タイミング
- ユーザが修正を採用した直後
- 「次の指摘どうぞ」 等の応答末尾に「skill 追記: ○○→○○ を対応表に追加した」 と1行告知 (自動追記の場合)
- ユーザの方針指示・反論があれば「注意点」 セクションに学びを記録

### 追記場所マッピング
| ユーザ提案の種類 | 追記先 |
|---|---|
| 単語置換 (A→B) | 平易化対応表 |
| 構文の回避例 | AI生成典型構文の回避例 |
| 新カテゴリ・観点 | 修正観点 |
| ワークフロー手順 | 修正ワークフロー |
| 媒体・用途別の例外 | 注意点 |
| ジャンル特有 (ブログ/メール/SNS等) | 別セクションを新設 |
