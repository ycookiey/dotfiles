# 内輪言及 / 構造化

観点(5)(10) の詳細。①A 因果は地の文へ / ①C 濃淡 / ①E 結び再統合 + So What / ②doctype メタルール も含む。

## (5) 内輪言及

- 「課題が言う」「本稿は」「先生が」など、その場限りの文脈に閉じた言及
- 出典は文末括弧で抽象化 or 受動形で文意保持
- 次節・他章への視覚的ナビゲーション: 「（次節）」「N 部で扱う予定」だけでは読者が迷う → 分担を対比構造で明示
- 書誌的説明: 「枠囲みで」「脚注で」など参照物の物理体裁は読者に不要

## (10) 構造化(階層・bullet・見出し)

- **bullet 末尾の名詞形 / 述語形を統一**: 「〜の難しさ」と「〜が難しい」を同一節で混在させない
- **並列 bullet の見出し名詞句は性質名で揃える**: 「○○の不足」「○○の少なさ」と性質名で並べるなら、形容詞+名詞も性質名化(例: 「能動的な参加者」→「参加者の能動性」)
- **見出しの太字は分割せず全体に**: `**A**(補足)**B**` →`**A(補足)B**`
- **見出しと bullet の意味的重複を避ける**
- **「ラベル: 値」形式の見出しは統合した名詞句に**: 「主なリスク: バイアス(様々な段階で生じうる)」→「**様々な段階で生じうるバイアスのリスク**」
- **ラベルを残す場合は `:` ではなく助詞 `は/を/が` で繋ぐ**: 「**本質**は、~」「**焦点**は、~」
- **指示語「これら」「その」は具体化**: 「これらの制約」→「**1 の制約**」のように番号参照
- **副詞の重ねを避ける**: 「定期的に批判的にまとめる」→「批判的にまとめ、定期的に更新する」
- **論理的齟齬を避ける**: 「考え方は運動」のように主語と述語の概念カテゴリーが不一致な表現は不自然
- **bullet 内の順序**: 一般説明 → 性質 → 例
- **「結論文 + 唐突な列挙導入」を避け繋ぎ文を入れる**
- **bullet 列挙の「結果/結論」は別段落に分離**
- **留意点・注意点は段落より bullet 化 + 理由を sub-bullet で構造化**
- **報告・活用の対象を主語に置き直す**: 「報告すべきは X」→「この判断は、X が報告すべき」
- **階層化で論理関係を示す**: 「根拠となる事実:」「示される事実:」ラベル + sub-bullet
- **オーバーフロー時はサイズ縮小ではなく分割**
- **順序性のある列挙は markdown 番号付きリスト**: 「第一」「第二」より `1.` `2.`。ただし単一段落の散文では番号リストを使えないため、接続詞「まず」「次に」「さらに」「加えて」で代替する(結びで「最後は」を使うなら、列挙の4番目に「最後に」を充てない)
- **小見出しに括弧補足を直接付けない**: 前置きや補足は別 bullet に独立
- **見出し(subtitle)はテーマを端的に**: 組織名・図名だけでなく概念や領域も入れる。硬い名詞句より並列が自然。本文と重複する年数等は不要
- **本文と見出しで文脈補完できる冗長表現は省略**
- **重要な引用句のみの bullet は意味不明**: 日本語訳併記、「発言:」ラベル + 訳
- **「意味するところ」のような要点明示ラベルを使う**
- **次セクションへの繋ぎは本文にも入れる**
- **括弧補足 `(...)` は最小限**
- **括弧の用語解説は同格で本文に溶かす**: 「用語(説明)」→「説明する用語」。括弧が複数並ぶ文ほど効果が大きい
- **「○○として」「(△△から)」のような意味のない括弧は文意に組み込む**
- **見出しの `:` 多用を回避**: 「〜: 〜」形式の見出しは AI 癖(既出の「ラベル: 値」を強化)。装飾記号「【】」「※」「◆」を見出しで多用しない
- **同一名詞・形容詞・接続詞の反復を避ける**: 「重要」を 3 回以上使うなら別語彙(「大切」「肝心」「核心」)に切り替える。「さらに」「また」の連続も避ける
- **指示語の連続多用を避ける**(書き言葉): 「その」「これ」「この」「それ」を連続使用しない。名詞を直接繰り返すか、別の指し方に置き換える(観点(8) の口頭指示語対応を書き言葉に拡張)

## 因果と経緯は地の文で書く。箇条書きは本当に並列なときだけ (文体憲法 第3条)

何でも箇条書きにするのは生成の癖。読み手が文章に対して抱く不満のうち最も強いのが、根拠の薄い箇条書きの羅列だった。ある事実が次の事実を引き起こすという経緯は、接続詞でつないだ地の文にする。箇条書きを使ってよいのは、項目が同じ文法構造・同じ抽象度で本当に並んでいる要点圧縮の場面に限る。

- Before: 「・在庫が減った ・発注担当が気づかなかった ・欠品が発生した」
- After: 「在庫が減っても発注担当が気づかず、そのまま欠品した。」

**見分けの基準**: 見出しの直後に箇条書きが3つ以上並んでいたら、項目間に「そのため」「だが」で言える関係が隠れていないか疑う。隠れているなら地の文に戻す。真の並列(議事録の決定事項一覧のように担当者と期日が独立していて因果でつながっていない)は箇条書きのままでよい。

## 濃淡設計 — 重要な節は厚く、軽い節は正直に軽く (文体憲法 第7条)

全項目を同じ厚み・同じ文型で書くのは、網羅を装う生成の癖。均等は怠慢に見える。特筆すべきことがない節は「この節に特別な示唆はない」と正直に書いてよい。列挙が4項目を超えるときは、上位2〜3項目に実例と数値を添えて厚くし、残りは一言で流す。

- Before: 「新機能Aは画面遷移を減らす改善である。新機能Bは表示速度を上げる改善である。新機能Cは文言を分かりやすくする改善である。」
- After: 「目立つ変更はAの一点で、発注画面の遷移を5クリックから2クリックに減らした。BとCは表示速度と文言の微調整で、体感できる差はない。」

**注意**: 濃淡は強弱であって順序づけではない。並列な項目や「どれにも等しく当てはまる」ことが主張の核である内容に、無理に順番や格付けを付けると、それ自体が生成の癖として表に出るうえ、主張の趣旨まで歪める。段階・順序・優先順位は、内容がもともとそれを持っているときだけ書く。

**検出の目安**: 全節が同じ文数(例: 各節 4 文)・同じ長さで並んでいる → 均等の疑い。3 文と 5 文が混在するのが自然。

## 結びは要約の繰り返しでなく再統合。レポート系は So What まで (文体憲法 第12条)

「以上、〜について解説した」という結びは、本文をもう一度なぞっているだけで新しい情報を運ばない。要点は 1〜2 文に再統合して締める。調査レポートは事実の記述で終わらせず、その結果から次に何をすべきかへの接続を最低 1 段落は書く。

- Before: 「以上、在庫管理システムの発注ミス削減について解説した。」
- After: 「発注ミスは人の注意力でなく、入力の設計で減らせる。次に着手すべきは、手入力の残る最後の画面をどう自動化するかだ。」

**注意**: So What には資格がいる。根拠が支える範囲を超えた処方(本文が「一部の少数派の行動」と留保しているのに「予算配分の前提に組み立てるべき」と締める等)は So What ではなく越権になる。書けるだけの根拠がなければ、無理に足さず事実の再統合で止めてよい。ガイドや議事録のように次章・次回への導線が別にある文書型では、この結びの段落自体が不要になることもある。

## 文書タイプが定まっていれば必須要素をチェック

文書タイプ(議事録・調査レポート・社内ガイド・企画書・スライド構成等)が定まっているなら、その型固有の必須要素をリストアップして欠落チェック。詳細は `references/doctypes.md` を参照。

**注意**: 必須要素チェックで欠落を見つけても、定型文の挿入で埋めるとボイラープレートになる。元文書がその要素を持たないのには理由があることも多い(そもそも不要な文書型の変種、著者の意図的な省略)。埋める前に「この文書に本当に要るか」を問い、要るなら文書固有の中身で書く。
