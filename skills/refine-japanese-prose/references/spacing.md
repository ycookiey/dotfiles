# 和欧混在時のスペース規則(プレーンテキスト出力時)

観点(11) の詳細。

## 背景

Markdown/LaTeX/HTML では組版エンジンが自動でアキを入れるため、ソースで空けなくてよい(むしろ二重アキになる)。プレーンテキスト(応募フォーム、メール本文、Slack、SNS、フォーム自由記述)ではソースの空白がそのまま可視化される。「日本語と英数字の間に全角/半角スペースを入れる」は AI 生成テキストの典型癖で、ネイティブは詰めるのが自然。

## 適用先

プレーンテキストの日本語(組版エンジンの自動アキが効かない出力先)。**本 skill 呼び出し時にプレーンテキスト出力があれば必ずチェック**。Markdown/LaTeX 内は組版エンジンに任せて基本ノータッチ。

## 規則

- **日本語と英単語・数字の間のスペースを詰める**
  - ❌ NG: `A 社 の SaaS を 3 年 使用` / `Web は Next.js で 実装`
  - ✅ OK: `A社のSaaSを3年使用` / `WebはNext.jsで実装`
- **英単語同士の間の半角スペースは保持**(元々の英語表記の一部)
  - ✅ OK: `Node.js Express` / `React Native` / `Google Cloud Platform`
- **数字と単位・接続語の間もスペースなし**
  - ❌ NG: `10 ヶ月 / 500 名 / 3 ヶ国`
  - ✅ OK: `10ヶ月 / 500名 / 3ヶ国`
- **括弧の内側と外側**
  - 括弧内が英数字だけ・括弧外が日本語 → 詰める: `TypeScript(3年)` / `Node.js(BE)`
  - 括弧内の英単語同士のスペースは保持: `(Next.js 14)` / `(App Router)`
- **例外**: 引用元や公式表記が空白を含む固有名詞・タイトル・URL(例: 論文タイトル、Twitter 名)は原文尊重

## 組版されない Markdown の扱い

判断基準は「組版エンジンを通すか」であって拡張子ではない。**組版を経ずそのまま読まれる Markdown**(`~/.claude/docs/` 配下の docs、リポジトリの README 等)は実質プレーンテキスト。

- この場合は**同じディレクトリの既存ファイルの和欧スペース有無を先に確認し、それに揃える**(詰める/空けるのどちらでも、文書群として一貫することが優先)
- 確認コマンド例: `grep -ohE "[ぁ-んァ-ヶ一-龥][0-9A-Za-z]+" <既存ファイル> | head`
