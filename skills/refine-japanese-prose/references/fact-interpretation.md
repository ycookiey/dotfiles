# 事実 vs 解釈

観点(7) の詳細。①D 確信度は明示ラベル(【要確認】等) で書き分けるルールも含む。

## (7) 事実 vs 解釈 (引用元と書き手の解釈を区別)

原典(本書/論文/サーベイ/参考文献)に基づく文書全般に適用。

- **基本事実と解釈の区別**: 引用元記載 + 一般辞書定義 = 直接掲載 OK。書き手独自の解釈 = 「これは解釈」と明示、または本文外(注・口頭補足)
- **原典で曖昧な語は限界を明示**: 「原典には明示されていませんが、私は ○○ と解釈しました」。「一般には ○○」より「私は ○○ と解釈しました」のほうが誠実
- **原典が示しているだけでは「なぜ?」と問われる**: 理由を解釈で補足
- **既存の例示と被る「私の理解」は無意味**: 新しい視点を加えるか、入れない
- **原典外情報は断定を避ける**: 「~です」より「~だと理解しています」「~だと考えられます」「~の一つでしょう」
  - ※注: 観点(4) の中庸結語回避と逆向き。**書き手の主張は断定が望ましいが、原典外情報や解釈は中庸表現で限界明示**。文脈で使い分け
- **原典外説明から原典記載に戻るときは合図**: 「原典の内容に戻ります」など
- **原典の前置きやニュアンス語から自分の言葉で言い換えない**: 修飾語を反映したつもりでも、原典にない断定(「~の問題だ」)は解釈
- **本文外の補足は明示的にラベル付け**: 「以下、原典にない補足:」のような sub-bullet 階層

## 確信度は明示ラベルで書き分ける (文体憲法 第10条)

全文に「〜と思われます」をまぶして確信度を均すのは逃げにすぎない。訂正履歴は冒頭近くに置き、未検証の内容は【要確認】と書き、推定にとどまる内容は「〜と推定する」と書く。断定・推定・未確認を語尾でなくラベルで書き分ける。

語尾のぼかしは書き手が責任の所在を決めずに済む。ラベルで書き分けるやり方はその逃げ道をふさぐ代わりに、断定した箇所については誤りを引き受ける覚悟を要求する。だが覚悟のいる箇所ほど、読み手が本当に知りたい箇所であることが多い。訂正を後から見つけたら、本文をひそかに書き換えず、冒頭に訂正の履歴を残す。

ラベルは【要確認】のように角括弧で目立たせ、本文の文体に紛れさせない。埋もれた「たぶん」は読み流されるが、独立した記号は読み手の目を止める。

### ラベルの型

- **【要確認】**: 未検証、事実確認が必要
- **【推定】**: 推定にとどまる、根拠が弱い
- **「筆者は〜と考える」**: 意見であることを明示
- **【訂正 YYYY-MM-DD】**: 訂正履歴(冒頭近くに置く)

### 検出の目安

- 「〜と思われます」「〜のようです」「〜かもしれません」が段落に複数回 → 語尾のぼかし。ラベルへ書き分け
- 事実と意見の境界が曖昧(同じ「〜だ。」形式で混在) → 意見側に「筆者は」「私見だが」を立てる
- 出典を示せない事実 → 事実として書かず、意見に格下げ(「〜と考える」)
