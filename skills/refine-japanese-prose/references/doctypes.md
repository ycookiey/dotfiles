# 文書タイプ別の必須要素

観点(10) 構造化 のメタルール「文書タイプが定まっているなら必須要素をチェック」の詳細。

各 doctype の答える問い・必須要素・AIがやりがちな失敗をまとめる。**必須要素チェックで欠落を見つけても、定型文の挿入で埋めるとボイラープレートになる**。元文書が要素を持たないのには理由があることも多い。埋める前に「この文書に本当に要るか」を問い、要るなら文書固有の中身で書く。

## 議事録

**答える問い**: 「何が決まり、誰が、いつまでに、何をやるか」。発言録ではない。

**必須要素**:
- 会議名・日時・参加者
- 議題ごとの議論の要点
- 決定事項
- 宿題(担当者と期日つき)
- 継続議題

決定事項・宿題・継続議題の3つは本文の議論から独立させ、末尾か冒頭にまとめて集約する。宿題は担当者・期日・内容の3点セット。欠けたら宿題ではない。「チーム全員で対応」「なるべく早く」は禁止。

**AIがやりがちな失敗**:
- 全発言を均等な熱量で要約 → 決定事項が他の意見と同じ重みで埋もれる
- 話者の確信度の平坦化 → 全員が言い切りになるか、逆に全員が「〜と思われる」になる
- フィラー(「えーと」)は消すが、話し言葉特有の冗長な言い回しはそのまま残す
- 核心発言を「測ってるからやって」→「測っているからやってほしい」と整形して生々しさを消す(話し言葉の引用は整形しない)

**重点観点**: (7) 確信度ラベル / (10) 因果は地の文・箇条書きは真の並列のみ / (10) 濃淡

## 調査レポート・分析レポート

**答える問い**: 「何が起きていて、次に何をすべきか」。データを集めて記述するだけでは調査は完結しない。

**必須要素**:
- 冒頭サマリー(結論と主要数値)
- 目的とスコープ
- 前提・母集団の定義
- 本題(調査結果)
- 方法(第三者が再現できる手順)
- データの限界
- So What(次に何をすべきかの提案)

方法とデータの限界は省略しない。誤読しやすい数字は該当する数字のすぐそばに注記(末尾に隔離しない)。

**AIがやりがちな失敗**:
- データを記述するところで力尽き、So What まで踏み込まない
- セグメント別の記述をすべて同じ文型で並べる(「Aチャネルは〜。Bチャネルは〜。Cチャネルは〜。」)
- 注意書きを末尾にまとめて隔離し、冒頭の数字だけが独り歩き
- 母集団の定義を明記しないまま数字だけ並べる

**重点観点**: (10) 結びは再統合 + So What / (7) 事実と考察の分離 / (10) 濃淡

## 社内ガイド・マニュアル

**答える問い**: 「読者が特定の作業を最短で完了できるか」。

**必須要素**:
- 対象読者・前提条件
- 手順(番号付き、順序性あり)
- 各手順の期待結果
- 例外・エラー時の対処
- 用語集(必要なら)

**AIがやりがちな失敗**:
- 手順の途中で解説を挟み、読者が「今どこにいるか」を見失う
- 前提条件を書かず「この記事の対象は〇〇」を最初に断らない
- 例外パターンを網羅しすぎて主線が読めない

**重点観点**: (17) 読者の3軸(知識・意欲・目的) / (4) 一般論導入定型「〜が求められています」を排除 / (10) 順序性ある列挙は番号付きリスト

## リサーチメモ・ディスカッションペーパー・企画書

**答える問い**: 「この論点について、次にどう判断すべきか」。結論より論点の整理が主。

**必須要素**:
- 論点の定義(何を議論するか)
- 現状把握
- 選択肢の列挙(2つ以上)
- 各選択肢の比較軸
- 判断に必要な追加情報 or 決めきれない理由

**AIがやりがちな失敗**:
- 選択肢を1つだけ提示して「これが最善」と結論を先取り
- 比較軸を挙げず、選択肢ごとに違う視点で評価
- 「判断に必要な追加情報」を書かず、決めきれない状態を隠す

**重点観点**: (7) 事実と解釈の峻別 / (10) 並列 bullet の性質名揃え / (4) 中庸結語は限界明示として活用

## スライド構成

観点(8) と統合して扱う。詳細は `speech-manuscript.md`。

**必須要素**:
- タイトルスライド(演題・発表者・日時)
- アウトライン(1枚)
- 各節(各節1メッセージ)
- まとめ(結論の再統合)

**AIがやりがちな失敗**:
- 各スライドに情報を詰め込み、聴衆が読めない
- 原稿とスライドが同じ内容(視覚と音声で冗長)
- アウトラインが「背景・課題・提案・まとめ」のラベル(結論なし)

## 学術レポート・輪講レポート

**答える問い**: 「この文献の要旨と自分の理解を、他の輪講メンバーに正確に伝える」。

**必須要素**:
- 書誌情報(著者・タイトル・出版年)
- 要旨(主張・方法・結論)
- 自分の理解と原典の区別
- 疑問点・議論したい論点

**AIがやりがちな失敗**:
- 原典の主張と自分の解釈を混ぜて書く(観点(7) 参照)
- 原典に明示されていないことを「一般には〜」と一般化して書く
- 硬い漢語・カタカナで原典を「翻訳」して馴染みにくくする
- 「本稿は」自己言及で始める

**重点観点**: (7) 事実 vs 解釈(原典依存の中核) / (1)(2)(3) 学術漢語・漢字連続・カタカナの平易化 / (16) 英語論文の翻訳調

## ブログ・note・エッセイ

**答える問い**: 「読者の時間を使ってでも読ませる価値があるか」。実用情報か体験・意見。

**必須要素**:
- タイトル(結論を含む)
- 冒頭の掴み(1〜3文)
- 本題
- 締め(次への接続 or 余情)

**AIがやりがちな失敗**:
- 「近年〜」「昨今〜」で一般論から始める
- 定型締め「参考になれば幸いです」「いかがでしたでしょうか」
- セラピスト構文・共感演出の乱用
- 全段落を同じ厚みで書く(濃淡なし)

**重点観点**: (4)(13)(14)(15) AI典型構文全般 / (12) リズム / (10) 濃淡設計

## メール・応募フォーム

**答える問い**: 「相手が読んで、次のアクションを取れるか」。

**必須要素**:
- 用件(冒頭1文)
- 根拠・詳細
- 相手に求めるアクション(あれば期限も)

**AIがやりがちな失敗**:
- 前置きが長い(「お世話になっております。〜」から本題まで数段落)
- 「〜させていただきます」の多用
- 和欧混在で全角/半角スペースが余分(観点(11))
- 締めの定型「よろしくお願いいたします」だけで具体的な次のアクションがない

**重点観点**: (11) 和欧スペース / (4) 定型締め・一般論導入 / (9) 「〜させていただく」冗長

## doctype に当てはまらない文書

タイプが定まらない/複数タイプが混在する文書は、doctype チェックを飛ばしてよい。17観点の一般ルールだけで進める。
