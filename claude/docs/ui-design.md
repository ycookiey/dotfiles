# UI デザインの指針(柔軟に使う)

厳格なルールではなく指針。状況に合わなければ外してよい。外すときは理由を一言添える。

## 情報の量
- 説明文で語らない。見出し・配置・形で伝わるなら、説明・凡例・列見出しは置かない
- 見せる前に、要素ごとに「ほかの場所や形で既に伝わっていないか」を見直し、重複は引く
- 理由を列で添えるより、理由になった値そのものを強調する。強調は効いた所(勝った側など)だけに絞る
- 「n-n」のように読み解きが要る書式より、1 つの量で示す

## 形と記号
- 文字のラベルより、意味の伝わるアイコン。絵文字は使わず SVG
- 種類の違うもの(グループとその中の項目など)は、形の役割で分ける。同じ部品の色違いにしない
- アイコンは対象に接して置き、揃えている側の端を動かさない(右寄せの列なら前、左寄せなら後ろ)。揃えるために空白を確保すると、対象から離れて近接が崩れる
- 記号の地と字のコントラストを確かめる(黄の地に白は読めない)

## 避けがちな定番
- 色付きの左の縦線、赤・緑の行の地色、大きな色付きの要約の枠は、ありがちな見た目になりやすい
- ほかで分かる要約の数字は置かない

## 操作
- 詳細を開いても本体の配置を動かさない(押した所の近くに重ねて出す)。入れ子で開くときは親を残す
- 重ねて出す窓は中身に合わせた幅にし、固定幅の余白を作らない
- 押せる物には見える手がかり(› など)を付ける。指を重ねたときの変化だけでは、スマホで伝わらない
- 効果が見て分からないボタンは、押した後に、変わった所へ目を導く動きを付ける(動きを減らす設定では省く)
- 見本・例を出すボタンは、何度押しても同じ結果にする

## 確かめ方
- 作ったら一度、上の観点で自分でレビューしてから見せる(引き算)
- PC とスマホの幅、明るい画面と暗い画面の両方で撮る
- グリッドの行に要素を足したら、列の数とずれないか確かめる(1 つにまとめる)

## 言葉
- 画面の言葉は、使う人の言葉にそろえる(例: 勝ち数→勝利数、時間割→タイムテーブル)
- 自分で作った呼び名は、初めて使うときに何を指すか書く。聞き返されたら、呼び名ごと言い換える
